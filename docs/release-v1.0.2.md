# 简截 v1.0.2 发布说明

> 这份内容与 GitHub Releases 页面上的正文一致。

修一个**偶发闪退**问题：点「提取文字」后程序偶尔会直接消失（托盘图标也没了）。

## 问题

Windows 事件日志里的记录：

```
错误应用程序名称: 简截.exe，版本: 1.0.1.0
异常代码: 0xc0000005          ← 访问违例
错误偏移量: 0x14d26
```

把偏移量对着编译产生的 `.map` 一查，落在 `ocr_recognize()` 里，具体是
`Language(L"zh-Hans-CN")` 创建 WinRT 对象的那一句 —— 通过 COM 激活工厂的虚表
调用时，缓存的工厂指针已经失效。

根因是 **OCR 跑在一次性的工作线程里，每次都要重新初始化 COM，并且多个线程会同时
去抢 C++/WinRT 那套进程级的激活工厂缓存**。这种竞态窗口很小，所以不是每次都能复现
（压测 18 轮、不同位置选区、连点 8 次都未必能撞上），但一旦撞上就是整个进程没了。

更糟的是 `0xc0000005` 属于 SEH 异常，`catch (...)` 默认**抓不住**它，
所以连"报个错"的机会都没有。

## 修复

三层防护：

1. **`/EHsc` 改成 `/EHa`** —— 让 `catch (...)` 也能接住访问违例这类 SEH 异常。
   现在就算再出问题，也只是面板上显示「识别时发生异常」，不会再闪退。
2. **两个工作线程整体包进 `try/catch`** —— 之前 OCR / 翻译线程里任何未捕获的异常
   都会触发 `std::terminate`，直接把进程带走。翻译那条路径原本连 `try` 都没有。
3. **串行化 WinRT 调用 + 防连点** —— `ocr_recognize` 内部加锁，
   面板处于「正在处理」时忽略新的提取请求，避免多个线程同时首次激活同一类型。

另外加了 `SetUnhandledExceptionFilter`：万一还有漏网的崩溃，异常码和地址会写进
`%LOCALAPPDATA%\JianJie\app.log`，不用再去翻事件查看器。

## 验证

用一个临时开关往 `ocr_recognize` 里注入空指针访问（`*(volatile int*)0 = 1`）：

| | 修复前 | 修复后 |
|---|---|---|
| 结果 | 进程直接消失 | 进程存活，面板显示「识别时发生异常」 |

注入验证完已把代码移除，正式包里没有这段。另外：

- 6 个回归脚本全过（重复截图 / 选区工具条 / 7 种标注 / 放大镜贴图翻译 / 保存 / 面板布局）
- OCR 压测 18 轮、6 个不同位置选区，无异常
- 日志里能看到 `OCR 线程异常（已拦截）`，确认走的是兜底分支
